Legenda

Relacionamentos

Herança — subclasse herda atributos e operações da superclasse (ex.: FlowConditionStep é um AutomationStep).

Composição (losango cheio) — o filho é eliminado junto com o pai: FK ON DELETE CASCADE (ex.: ChatSession ◆ Message).

Agregação (losango vazio) — o filho sobrevive ao pai: FK ON DELETE SET NULL (ex.: Automation ◇ AutomationRun).

Associação — referência lógica sem FK em cascata (ex.: Message — MessageFeedback).

Dependência (tracejada) — uso temporário: o JSON de Automation é validado pelo esquema AutomationPlan.

Multiplicidades

NotaçãoSignificado
1exatamente um
0..1nenhum ou um (FK anulável / SET NULL)
0..*zero ou muitos
1..*um ou muitos (obrigatório)

A leitura é feita de cada extremidade: em Profile "1" ◆ "0..*" ChatSession, cada perfil possui de zero a muitas sessões e cada sessão pertence a exatamente um perfil.

Princípios SOLID observados na camada de domínio

  • S (Responsabilidade Única): cada classe modela exatamente uma entidade/tabela; regras de negócio ficam em services e consultas complexas em repositories.
  • O (Aberto para extensão): novas entidades entram como novas classes, sem alterar as existentes.
  • L/I (Substituição e interface única): todos os models persistem pela mesma interface CRUD — salvar(), atualizar(), deletar(), listar_todos(), buscar_por_id(), to_dict() — e são intermutáveis nas camadas acima.
  • D (Inversão de dependência): controllers e services dependem dessa interface, não de detalhes de persistência.

Observação: PageAnalysisCache é um cache global indexado por url_hash, sem chaves estrangeiras, por isso aparece sem relacionamentos.
